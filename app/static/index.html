Cryptographic Decisions & Technical Justifications

Primitive 1

ChaCha20-Poly1305 vs. AES-256-GCM

AES relies on software lookup tables (S-Boxes) susceptible to cache-timing side-channel attacks when hardware acceleration (AES-NI) is absent. ChaCha20 uses simple Add-Rotate-XOR (ARX) operations executing in strictly constant time across all CPU architectures.

Metric ChaCha20-Poly1305 AES-256-GCM
Design Architecture Constant-Time ARX Substitution-Permutation
Timing Vulnerability Immune (Constant-Time) Vulnerable without AES-NI
Key & Nonce 256-bit Key / 96-bit Nonce 256-bit Key / 96-bit IV
Industry Standard RFC 8439, TLS 1.3 NIST SP 800-38D, TLS 1.3
Primitive 2

ECC (ECDH / ECDSA) vs. Legacy RSA

Based on the algebraic structure of elliptic curves over finite fields, ECC achieves 128-bit security level with a compact 64-byte key compared to a cumbersome 384-byte key for RSA-3072. Handshake speed is 10× to 25× faster with drastically lower memory overhead.

Metric ECC (P-256) RSA-3072
Public Key Size 64 Bytes 384 Bytes (6× larger)
Sign Operation ∼0.1 ms ∼2.5 ms
Resource Profile Low Footprint High Exponentiation Load
Shor's Algorithm Vulnerable (Quantum) Vulnerable (Quantum)
Primitive 3

DSA vs. ElGamal Signatures

Raw ElGamal signatures produce oversized signatures modulo a large prime modulus p. DSA was specifically standardized by NIST to operate in a prime-order subgroup, generating compact signatures (∼64 bytes via ECDSA) with significantly faster verification.

Scheme Signature Size Arithmetic Complexity
ElGamal Signatures 2× Modulus Length Full-Modulus Exponentiation
DSA / ECDSA Compact (64 bytes) Subgroup Curve Operations
PQC Anchor

NIST FIPS 203 ML-KEM-768 (CRYSTALS-Kyber)

Kyber relies on the hardness of the Module Learning With Errors (M-LWE) problem in structured module lattices. No known quantum algorithm (including Shor's or Grover's) can solve M-LWE in polynomial time, guaranteeing long-term post-quantum secrecy.

Parameter Value Cryptographic Purpose
Public Key (pk) 1,184 Bytes Encapsulation token for sender
Secret Key (sk) 2,400 Bytes Decapsulation token for receiver
Ciphertext (ct) 1,088 Bytes Quantum-resistant key encapsulation
Shared Secret (ss) 32 Bytes HKDF seed for payload key & stego seed
